One photograph, four questions

Buses, cars, motorbikes, people, buildings. What could a vision system tell us?

  1. What is in this image? Classification. One answer for the whole picture.
  2. Which other images look like this one? Visual search.
  3. What objects are where? Detection: a box and a class for each object. Segmentation: a label for the pixels.
  4. Can a model trained somewhere else do this? That is transfer, later in the day.

How a neural network learns

A neuron multiplies each input by a weight, adds a bias, and passes the sum through a nonlinearity. A large weight means that input pushes the output a lot. The bias is an offset. The nonlinearity, often a ReLU, lets the network compute more than a straight line.

A layer is many neurons looking at the same input. A network is layers in a row: the output of one is the input of the next. Running an input from start to end is the forward pass. The last layer gives one score per class, the logits. A softmax turns those scores into probabilities.

Learning is a loop. Predict, with the forward pass. Score the prediction with a loss. For classification, cross-entropy is small when the network puts high probability on the right class. Backpropagation uses the chain rule to say, for every weight, how the loss would change if that weight changed a little. Then each weight steps a little in the direction that reduces the loss.

We never tell a hidden layer what to compute. Training shapes it into whatever intermediate features help reduce the loss. Those are learned representations. Today’s question: when the input is an image, what features does a network learn, and does the wiring matter?

An ordinary network is a poor fit for images

Flatten a 224 by 224 color image and you get 150,528 numbers. Connect that to one hidden layer of a thousand neurons and every neuron needs a weight for every input: about 150 million weights, in that layer alone.

The deeper problem is not the count. Shuffle every pixel with one fixed permutation, and do the same shuffle to every training image. A fully connected network learns the shuffled pictures as easily as the real ones. It has no idea which pixels were neighbors. The arrangement of the image never entered the computation.

Two assumptions fix both problems. Locality: an edge, a corner, or a bit of texture depends on a small neighborhood, so each unit looks at a small patch. Weight sharing: an edge detector that is useful in one corner is useful in another, so the same weights are used everywhere. That is a convolution, the same operation as yesterday, except the kernel is learned.

Locality is the wrong assumption when the answer depends on something far away, such as water on the other side of the image, and when the data does not live on a grid at all. Day 5 lets every patch look at every other patch.

The parts of a convolutional network

A real convolution layer has many filters, and each filter looks at all the channels. The building block is convolve, then ReLU, then pool. Pooling keeps the strongest response in a small window and throws away the exact position inside that window. Stack the blocks and the receptive field grows: a unit near the top sees a large part of the image, built from the small patches the first layer saw.

Early layers respond to edges and simple texture. Later layers respond to parts and objects. The feature maps are the representation. Two images that produce the same maps are metamers for that layer, the idea from Day 3.

The stack of convolutional layers is the backbone. The last layers, which turn those features into class scores, boxes, or masks, are the head. Train the backbone on a large set such as ImageNet, throw away the head, and attach a new one. That is transfer.

Convolution is equivariant to a shift: move the object and the feature map moves with it. After enough pooling, the class label is approximately invariant: the name stays the same when the object moves.

What is still open, and the lab

A CNN is not a finished story. Can a network learn to follow one voice at a noisy party, and does it then succeed and fail where people do? Can it know when it does not know? Those are questions people are working on now.

In the lab you test the claim on handwritten digits. You train a fully connected network as a baseline, then build a CNN, look at its learned filters, and shuffle the pixels. The notebook is Handwritten digits, in Colab. Lecture 2 asks what it means to recognize an object once the features exist.
