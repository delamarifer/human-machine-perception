Adapting existing models

Chapter 37 frames adaptation with a farm. Last season a drone learned a model f for fields of wheat and corn. This season the corn has become soybeans. The old model can only answer with the classes it was trained on, so it calls the soybeans “corn”. Start from f, not from scratch, to get f′, which answers {wheat, soybeans}. Pretraining is how prior knowledge is acquired in the first place. Adaptation is how it is used to solve a new task.

Training from scratch is data hungry. Starting with prior knowledge is data efficient. The methods are fine-tuning, domain adaptation, test-time adaptation, continual learning, monitoring, and human feedback loops. In fine-tuning, you can freeze some layers, fine-tune others, and train a new head from scratch (Fig. 37.3).

Fine-tuning in symbols. Start from the pretrained weights, θ0 = θpre. Put a new head on the features, f′(x) = W · gθ(x). Train on the new labeled images with L = (1/N) Σi CE(f′(xi), yi), taking gradient steps θ ← θ − η ∇θL with a small η so the weights stay near θpre. Fine-tuning subparts splits the parameters into frozen ones (never updated), fine-tuned ones (small steps) and a new head (bigger steps).

Which layers to fine-tune is a choice you test on a validation set. Early layers learn general features such as edges and textures, which transfer widely, and later layers are more specific to the original task (Yosinski et al., NeurIPS 2014). With little data, train only the head or the head and the last block. With more data, or a task far from the pretraining data, unfreeze more. In practice: start with the head, unfreeze one more block at a time, and stop when validation accuracy stops improving.

In PyTorch, start from a network pretrained on ImageNet. Turn off gradients for the layers you freeze, leave them on for the block you fine-tune, and replace the last layer with a new one for your classes. The fine-tuned block gets a smaller learning rate than the new head, so it stays close to what it already learned.

import torch, torch.nn as nn, torch.nn.functional as F
from torchvision import models

num_classes = 3                                    # your new task, e.g. wheat, soybeans, other
model = models.resnet18(weights=models.ResNet18_Weights.DEFAULT)  # f: pretrained on ImageNet

for p in model.parameters():                       # frozen: keep what f learned
    p.requires_grad = False
for p in model.layer4.parameters():                # fine-tuned: the last block adapts
    p.requires_grad = True
model.fc = nn.Linear(model.fc.in_features, num_classes)  # from scratch: a new head

optimizer = torch.optim.Adam([
    {"params": model.layer4.parameters(), "lr": 1e-4},   # small steps: stay close to f
    {"params": model.fc.parameters(),     "lr": 1e-3},   # larger steps: new weights
])

model.train()
for x, y in loader:                                # your labeled images for the new task
    loss = F.cross_entropy(model(x), y)
    optimizer.zero_grad()
    loss.backward()                                # frozen layers get no gradients
    optimizer.step()

Our code (PyTorch and torchvision). loader is a DataLoader of your images and labels. To fine-tune all layers, as in the fog example below, leave every requires_grad on. To train only the head, freeze layer4 too.

An example: driving in the fog (Sakaridis, Dai and Van Gool, IJCV 2018). A model trained on 2,975 clear images was fine-tuned on 498 synthetic fog images and tested on 101 real fog images. Mean IoU rose from 34.9% to 37.8% over all classes, and from 52.4% to 57.4% on the frequent classes.

Learning from a teacher

Learning from examples is like an answer key with no explanations: the label says “cat”. A teacher can say “cat 90%, tiger 10%”, which explains that this is a tiger-like cat. Supervised learning is a teacher that puts all its belief on one class. A model as teacher gives partial credit to similar classes, so each image carries more information.

Knowledge distillation (Hinton, Vinyals and Dean, 2015) softens the teacher’s outputs with a temperature: pi = exp(zi/T) / Σj exp(zj/T). In the slide’s example, at T = 4 the teacher’s probability for “cat” falls from 0.77 to 0.40 and “tiger” rises to 0.28. The student is trained on L = α · T² · KL(p ‖ q) + (1 − α) · CE, where the KL term matches the teacher’s soft targets and the cross-entropy term matches the true label. With α = 0.5, the example gives KL 0.056, CE 0.571 and L 0.730. In offline distillation the teacher is frozen and only the student learns.

Where the KL of 0.056 comes from, class by class at T = 4:

The teacher puts more weight on cat and tiger than the student does; the student spreads too much onto giraffe and dog. Scaled by T² and weighted by α, the KL term is 16 × 0.056 × 0.5 = 0.445; the label term is 0.571 × 0.5 = 0.286; together 0.730.

In PyTorch, the loss is a few lines. The teacher runs under torch.no_grad(), so gradients reach only the student. Here the teacher is the fine-tuned ResNet-18 from above (about 11 million parameters), and the student is a MobileNet with about 1.5 million.

def distillation_loss(student_logits, teacher_logits, labels, T=4.0, alpha=0.5):
    p = F.softmax(teacher_logits / T, dim=-1)          # soft targets
    log_q = F.log_softmax(student_logits / T, dim=-1)
    kl = F.kl_div(log_q, p, reduction="batchmean") * T * T
    ce = F.cross_entropy(student_logits, labels)       # the true labels
    return alpha * kl + (1 - alpha) * ce

teacher = model                                        # the fine-tuned model from above
student = models.mobilenet_v3_small(num_classes=num_classes)  # smaller, trained from scratch
optimizer = torch.optim.Adam(student.parameters(), lr=1e-3)

teacher.eval()                                         # offline: frozen
student.train()
for x, y in loader:
    with torch.no_grad():
        teacher_logits = teacher(x)                    # forward pass, no gradients
    student_logits = student(x)                        # forward pass
    loss = distillation_loss(student_logits, teacher_logits, y)
    optimizer.zero_grad()
    loss.backward()                                    # gradients reach only the student
    optimizer.step()

Our code (PyTorch), the same loop as on the slide; loss as in Hinton, Vinyals and Dean (2015). With the slide’s example logits, distillation_loss gives KL 0.056, CE 0.571 and L 0.730, the same values as above. F.kl_div takes the student’s log-probabilities first and the teacher’s probabilities second. The factor T² keeps the soft-target gradients on the same scale as the label term.

Use cases: efficiency, with a smaller or faster student (Chen et al., NeurIPS 2017); Learning without Forgetting, where an ImageNet classifier is extended to a new task such as scene recognition (Li and Hoiem, ECCV 2016); and privacy, where teachers trained on private data label public data for a student (PATE, Papernot et al., ICLR 2017).

Catastrophic forgetting and continual learning

In our toy run on 8×8 digits with a small network, each new rotation (0°, 30°, 60°, 90°, 120°) is learned to 0.97–0.98. With plain fine-tuning, accuracy on the original 0° task falls from 0.98 to 0.18. This is the motivation for continual learning. Replay keeps a few old images (5 per digit, per angle) and mixes them into each batch. EWC (Kirkpatrick et al., PNAS 2017) keeps no images. It saves each weight’s value and its importance for the old task, then adds a penalty, like a spring, for moving important weights. Average accuracy at the end, mean of three seeds, when the digits rotate: fine-tune only 0.45, EWC 0.62, replay 0.88, all data at once 0.97. When new digits arrive: fine-tune only 0.20, EWC 0.20, replay 0.89, all data at once 0.97.

When to use each method

  • Some labeled examples: fine-tuning.
  • Many unlabeled examples: domain adaptation.
  • Only the live stream: test-time adaptation.
  • A world that keeps changing: continual learning.
  • Any of these, after launch: monitoring.
  • Failures that people can label: human feedback loops.

Agents and memory

Where does learning live?

Today’s methods put what a model learns in three places: in the weights (fine-tuning), in a smaller model (knowledge distillation), or in the context, kept across sessions (agent memory). The last one leaves the weights alone.

From model to agent

A model rarely works alone. It sits inside a loop: perceive (a screen or a camera), decide, act, remember. The environment gives an image; perception models detect objects, segment and estimate depth; the agent, often a vision-language model, plans and picks the next action given its task; actions such as clicking, typing, moving an arm or grasping change the world, which gives a new image. Memory is read and written along the way.

One pass, for the task “put the mug in the sink”: see the camera frame; perceive the mug and the sink; decide to grasp the mug by its handle and move right; act, and a new frame arrives; remember a note for next time, such as “mugs: grasp by the handle”. The slide’s example is illustrative, not a real run.

Current challenges

As at the weight level, agents forget, here on long-horizon tasks, when early steps no longer fit in what the model can see at once. And context has to be shared across sessions, or across several agents working on one task.

Memory in humans

Long-term memory is often split into explicit (declarative, with conscious recall: semantic facts and episodic events) and implicit (non-declarative: procedural skills and emotional conditioning); the slide’s tree is based on Malmberg et al. (2019). Four ideas carry over to agents:

  • Hippocampus. It captures experiences fast and keeps an index that points to traces across the cortex (Teyler and DiScenna, 1986). In an agent: transcripts, notes and an index file.
  • Replay during sleep. Recent experiences are replayed and slowly folded into the neocortex, a slow learner that would be disrupted by fast changes (McClelland, McNaughton and O’Reilly, 1995). In an agent: “dreaming”, an offline pass over past sessions.
  • Existing schema. New information that fits what you already know is consolidated faster (Tse et al., 2007). In an agent: add to an existing page rather than a new file.
  • Recalling a memory. Recall makes a memory editable again (Nader, Schafe and LeDoux, 2000). In an agent: a note is checked and corrected when it is read.

Fast and slow stores kept apart is the same idea as avoiding catastrophic forgetting: quick changes to one shared store overwrite what it knew.

Agent memory

One way to organize an agent’s memory (Martin, The components of agent memory, 2026), from bottom to top:

  • Transcripts: a complete, searchable event log.
  • Memory notes: salient observations the agent writes down, marked checked or unconfirmed.
  • Memory representations: pages computed from transcripts and notes, linked to each other, such as a wiki.
  • Injected context: a small amount loaded into every session, such as the current goal and an index.

Each layer up is smaller and more abstract. Dreaming is an offline pass that reads the transcripts and updates the layers above: it writes notes, builds and links pages, and promotes what every session needs. Reading goes the other way: injected context is always loaded, wiki pages are followed by their links, transcripts are searched. Dreaming also corrects: in one example from the post, a wrong note (“Mt Moon DONE”) made a game-playing agent loop; checked against the transcript, the note was fixed and the agent got through. Links carry much of the knowledge: one dreamed wiki grew from 103 pages and 766 links after 2 sessions to 222 pages and 12,893 links after 128.

Open questions remain about memory beyond text (images, embeddings, maps of a scene) and about how to structure stored pieces and their relations. Papers to start with:

  • Packer et al., MemGPT: Towards LLMs as Operating Systems (2023)
  • Lin et al., Sleep-time Compute: Beyond Inference Scaling at Test-time (2025)
  • Fang et al., Trajectory-Informed Memory Generation for Self-Improving Agent Systems (2026)
  • Martin, The components of agent memory (2026)
